# Lightek Design Studio

Open **Settings → Design Studio**, or **Website designs & fonts → Open Design Studio**.

## Designer workflow

1. Give the design a name and start from a blank canvas, VinylCTRL, YBNC or an available released design.
2. Add, select, duplicate, remove and reorder sections. Drag sections or use their arrow buttons. Clicking a section in the preview selects it in the inspector.
3. Edit the section's content. Collection sections have add/remove controls for cards and statistics. Original client sections retain their declared editable fields; use the field search to find text or links quickly.
4. Set section anchors for in-page links. Layout controls include spacing, content width, alignment, columns, corners, background and text colors. The new design blocks provide the most direct control of those settings. Original client sections retain their source markup and styling; controls on those sections affect their wrapper and supported overrides.
5. Open Design settings to change the palette, base style and typography. The existing visual Google Fonts browser remains available for body, heading and monospace choices.
6. Upload an image from the relevant image field, or select an image already uploaded to that design workspace. Uploads use the existing DymondCompute storage service. PNG, JPEG, GIF and WebP images up to 10 MB are supported.
7. Use Desktop, Tablet and Mobile preview sizes. The preview is sandboxed, debounced and read-only; editing a preview does not write website content.
8. **Save draft** stores the workspace. **Add to design library** creates an immutable version available in Website designs & fonts. Applying a design, importing its starter page and publishing website pages are separate actions.

The built-in blocks are Hero, Text, Image & text, Cards, Statistics, Call to action, Image and Footer. Existing registered Lightek sections can also be used. This is a visual section designer; its controls generate the data, editable schema and runtime section registrations together. Designers do not assemble manifests, write Ruby files or restart Rails to release a design.

## Versions and ownership

Drafts belong to their creator. Administrators can work on their own designs; super admins can work on all design workspaces. Library choices are scoped to the creator, with super admin visibility across creators, plus the currently active version on an authorized website. Existing website ownership checks still govern application and import.

Save and release operations check a draft revision under a row lock. A stale browser tab receives a conflict instead of overwriting the newer draft. Keep that tab open if a save fails. Reload after preserving any text you still need.

A new library version never replaces an older version in use by a client. Applying a new version is explicit. Releasing unchanged content reuses its existing version. Imported starter pages remain drafts, and repeated imports preserve edited pages through the existing import service.

A website's template copy also stores its design definition snapshot. Drafts and releases are ordinary records in the existing SiteTemplate system, so they participate in normal database backups. Runtime support is application source. Moving a website to another installation still uses its normal website/database and media deployment process.

## Storage and runtime

No database migration or new gem is required. Workspaces use SiteTemplate records prefixed `ld_document_`; immutable releases use `ld_release_`. Metadata is kept under `lightek_studio`, `lightek_studio_release` and `lightek_studio_snapshot`. Internal records are excluded from the legacy template editor to preserve their schemas and immutable versions.

Public rendering resolves its design by key and caches it within the Rails execution context. Workspace lists are paginated and ownership-filtered in the database; library choices load the current author’s released designs (or all authors for super admins). Section classes are registered when needed, and no view/source files are generated by a save or release. Preview requests are debounced and superseded requests are cancelled by the editor. The application validates the supported schema, limits designs to 30 sections and caps collections at 30 items.

Client pages, publication flags, website names, navigation records and template customization copies remain in the existing systems. The existing visual font picker and public navigation corrections are included in the installation path where relevant.

## Install and verify

```bash
cd ~/Desktop/Development/lightekmcg-site
bash ~/Downloads/lightek_design_studio_install.sh
APPLY=1 bash ~/Downloads/lightek_design_studio_install.sh
```

The first command is a dry run. The second makes backups, installs the source and runs the autoload check plus the font, design and Studio tests in the host's test environment. It makes no production design records during installation. Restart Rails after the checks pass, then open `/dashboard/design-studio`.

The backup directory includes `restore.py`, which refuses to overwrite files changed after installation.

Local verification used Active Record and Action View 8.0.4 with the supplied DymondSite models: 16 combined service tests, 121 assertions, no failures. Blank, VinylCTRL and YBNC Studio previews rendered successfully. Chromium checks exercised actual Rails-rendered preview responses and the editor's text editing, add/reorder/duplicate/remove controls, save/revision requests, library-release request and mobile sizing without JavaScript errors. Full-host HTTP tests are bundled and run by the installer in the actual checkout.
