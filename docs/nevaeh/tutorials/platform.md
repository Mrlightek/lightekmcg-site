# Mail, payments, hosting and other platform modules

The live capability reference distinguishes installed registrations from connected operating adapters. A database record and a complete business workflow are not the same interface.

## Find the supported route

1. Search Guide for the module or capability name.
2. Check connected/disabled/adapter_needed availability.
3. Inspect the input schema or its documentation gap and linked domain manual.
4. Use the domain interface for financial, hosting, mail and publishing workflows.
5. Verify downstream state and evidence after execution.

## Installed manuals

Software Library includes the version installed with this server. Search for Mail operations and sending controls; Dymond Bank lifecycle; Marketplace; Customer fleet updates; Server application management; Reservations and payouts; Studio broadcasting and native workstation workflows.

These manuals remain useful even when a module has not exposed a conversational adapter. You can query authorized ordinary data through /models and the console, but a raw write is not a substitute for sending mail, settling a payment, provisioning a server or publishing a stream.

## Missing adapters or documentation

Use the reference's documentation request action to prefill a ticket with the exact capability. Include the outcome, current input/schema gap and expected acceptance evidence. Unsupported operations must be implemented and registered rather than guessed from documentation.

A new GitHub repository watcher creates an onboarding packet, not an automatic production deployment. Review runtime, dependencies, configuration, target and acceptance checks, then connect a supported deployment worker.
