# Lightek Studio roadmap

## Phase 1 — Studio v2 foundation (current)

- Preserve Blender manifest/execution kernel
- Introduce `Production`
- Replace forward-facing `CreationJob` model with universal `StudioOperation`
- Provider registry with Blender adapter
- Reusable artifact ownership
- Gatekeeper authorization boundary
- Vault credential boundary
- Publication and live-operation domain models
- Reserve TikTok, Instagram, Facebook, Lightek Social, and Lightek Streaming adapters

## Phase 2 — Studio workspace UI

- DymondDash-native Studio shell
- WebGL/Three.js GLB viewport
- Scene hierarchy and inspector
- Nevaeh Director command surface
- Transform gizmos and property panels
- Asset library and direct uploads
- Turbo Stream operation progress
- Productions, versions, approvals, and artifact browser

## Phase 3 — production engines

- FFmpeg provider
- video timelines and assembly
- Geometry Nodes parameter packs
- rigging and animation tracks
- text, curves, logos, and motion graphics
- poster/thumbnail/social derivative generation
- render chunking, retries, cancellation, and quotas

## Phase 4 — distribution

- TikTok publishing adapter
- Instagram publishing adapter
- Facebook publishing adapter
- Lightek Streaming publishing adapter
- publication scheduler and reconciliation jobs
- captions, metadata, subtitles, destination presets, and delivery analytics
- Vault-backed OAuth/token lifecycle

## Phase 5 — Nevaeh live

- TikTok live adapter first
- run-of-show model
- live scene/overlay/media control
- comment ingestion
- KB-backed audience response
- moderation capability set
- human approval/escalation rules
- trouble-ticket learning loop
- stream-health monitoring

## Phase 6 — Lightek production cloud

- Linode worker pools and dedicated plan-backed nodes
- Gatekeeper compute routing
- GPU/CPU capability scheduling
- storage/bandwidth quotas
- Dymond Bank project budgets and `PaymentQuote` integration
- usage metering and customer Studio plans

## Phase 7 — native social destination

- Lightek Social implements the Studio publisher contract from day one
- native post/live ingestion from Studio
- profiles, follows, feed, comments, reactions, reposts, discovery, communities, notifications, and moderation
- Studio artifacts remain the canonical production assets; Social remains the audience/discovery layer
